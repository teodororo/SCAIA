Modos

Uma action, dois modos

O input mode decide o que a action lê e para onde ela escreve os achados.

mode: pr padrão

Revisão do pull request

Lê o diff do PR e devolve os achados como comentários inline nos pontos vulneráveis.

  • Dispara em eventos pull_request
  • Precisa de pull-requests: write
  • Não exige actions/checkout
  • Não tem acesso ao resto do código do repositório.
mode: full

Scan do repositório inteiro

Lê os arquivos versionados (git ls-files) em lotes e grava um relatório Markdown + Job Summary.

  • Roda em push, schedule, workflow_dispatch
  • Basta contents: read
  • Exige actions/checkout
  • Saída em report-path, pronta para virar artifact

Integração

Adicione em minutos

Workflows completos e prontos para copiar em .github/workflows/. Só é preciso criar o secret com a chave do seu provedor de IA.

.github/workflows/scaia-pr.yml 
# Revisa o diff de cada pull request e comenta inline nos pontos vulneráveis.
name: Revisão do SCAIA - modo PR

on:
  pull_request:

permissions:
  contents: read
  pull-requests: write

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: teodororo/SCAIA@v2
        with:
          api-token: ${{ secrets.AI_API_TOKEN }}
          model: gpt-4o
.github/workflows/scaia-full.yml 
# Escaneia o repositório inteiro e publica o relatório ao fim da execução.
name: Revisão do SCAIA - modo full

on:
  workflow_dispatch:
  schedule:
    - cron: "0 6 * * 1" # toda segunda às 06:00 UTC

permissions:
  contents: read

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4 # obrigatório no modo full

      - uses: teodororo/SCAIA@v2
        with:
          mode: full
          api-token: ${{ secrets.AI_API_TOKEN }}
          model: gpt-4o

O relatório é gravado no repositório clonado e aparece no resumo da execução, sem precisar de mais nada.

.github/workflows/scaia.yml 
# Um arquivo só: revisa cada pull request e escaneia o repositório toda semana.
name: Revisão do SCAIA

on:
  pull_request:
  workflow_dispatch:
  schedule:
    - cron: "0 6 * * 1" # toda segunda às 06:00 UTC

jobs:
  pr:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: teodororo/SCAIA@v2
        with:
          api-token: ${{ secrets.AI_API_TOKEN }}
          model: gpt-4o

  full:
    if: github.event_name != 'pull_request'
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4
      - uses: teodororo/SCAIA@v2
        with:
          mode: full
          api-token: ${{ secrets.AI_API_TOKEN }}
          model: gpt-4o

Um job por modo, cada um com a permissão que precisa: o do pull request escreve comentários, o do scan só lê. O if garante que cada evento dispare apenas o job certo.

Referência

Inputs e outputs

A mesma lista vale para os dois modos. Só api-token e model são obrigatórios.

Input Padrão Descrição
api-token obrigatório — Chave de API para o provedor de IA escolhido.
model obrigatório — ID do modelo a usar (ex: gpt-4o).
mode opcional pr pr revisa o diff do pull request; full escaneia o repositório inteiro (exige actions/checkout).
api-base-url opcional api.openai.com/v1 URL base do endpoint Chat Completions.
max-files opcional 500 Limite de arquivos enviados à IA em uma execução.
include opcional — Globs dos arquivos a revisar no scan completo. Vazio = todos os arquivos versionados.
exclude opcional — Globs de arquivos a ignorar, separados por vírgula ou quebra de linha.
temperature opcional — Controla o quanto o modelo varia nas respostas (0-2). Vazio = o modelo decide.
system-prompt opcional embutido Override do prompt de sistema do revisor.
min-confidence opcional 0.8 Confiança mínima (0–1) para um achado ser publicado, aplicada após a verificação.
fail-on-findings opcional false Falha o job quando qualquer achado é reportado.

Outputs: findings-count — número de achados publicados; report-path - caminho do relatório Markdown gerado.

Destaques

Traga seu próprio modelo

🔑

Seu token, seu custo

Nenhum segredo passa por servidores de terceiros. A chave de API vai direto do seu repositório para o provedor.

🔌

Qualquer provider

OpenAI, OpenRouter, Anthropic via proxy, Mistral, Groq ou modelo self-hosted — qualquer endpoint /v1/chat/completions.

🔁

Dois modos, um setup

O mesmo provider e os mesmos filtros servem ao PR do dia a dia e ao scan periódico do repositório inteiro. Muda só o mode.

💬

Comentários inline

No modo pr, os achados vão para as linhas exatas do diff. O que fica fora do alcance é incluído no resumo da revisão.

📄

Relatório versionável

No modo full, os achados viram um Markdown agrupado por severidade — artifact do workflow e Job Summary.

🎯

Achados verificados

Toda descoberta passa por uma segunda opinião do modelo e pelo corte de min-confidence antes de ser publicada.
